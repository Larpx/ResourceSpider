# ResourceSpider 开发计划

## 项目概述

ResourceSpider 是一个轻量、灵活、高性能、跨平台的分布式网络爬虫框架，采用 Agent-Server 架构，支持本地模式和分布式模式。

---

## 技术栈选型

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 服务端框架 | ASP.NET Core 11.0 | Web API 框架 |
| ORM | SqlSugar.Core | 数据访问 |
| 缓存 | StackExchange.Redis | Redis 客户端 |
| 消息队列 | MassTransit + RabbitMQ/InMemory | 消息总线抽象 |
| HTTP 客户端 | HttpClient + Refit | HTTP 请求 |
| 无头浏览器 | Playwright.NET | 浏览器自动化 |
| 日志 | Serilog | 结构化日志 |
| 认证 | JWT Bearer | 身份认证 |
| 测试框架 | xUnit + FluentAssertions + Moq | 单元测试 |

## 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| Playwright.NET 性能问题 | Agent 采集效率下降 | 使用对象池管理浏览器实例，合理设置生命周期 |
| RabbitMQ 部署复杂度 | 运维成本增加 | 提供 InMemory 模式作为开发/测试默认选项 |
| 大数据量去重 | 内存占用过高 | 使用 BloomFilter 或 Redis 去重方案 |
| 分布式数据一致性 | 数据重复或丢失 | 实现幂等性设计和补偿机制 |
| 前端开发进度 | 项目延期 | 可考虑使用成熟后台模板（如 Ant Design Pro） |

## 后续建议

1. **优先开发核心模块**: 消息队列、调度器、下载器是核心，优先保证稳定
2. **迭代开发**: 先实现最小可用版本，再逐步完善功能
3. **测试驱动**: 核心模块建议先写测试用例，再实现功能
4. **文档同步**: 代码注释和文档应同步更新，避免后期补文档
5. **代码审查**: 每个阶段完成后进行代码审查，确保质量
